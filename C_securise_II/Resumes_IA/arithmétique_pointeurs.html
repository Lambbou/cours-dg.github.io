L'Arithmétique des Pointeurs en C 📐

L'arithmétique des pointeurs est une des fonctionnalités les plus puissantes et distinctives du C. Elle permet de naviguer dans la mémoire de manière efficace, mais elle est très différente de l'arithmétique sur les entiers.

Le Principe Fondamental

Une arithmétique basée sur le type

Quand vous ajoutez 1 à un pointeur, vous ne lui ajoutez pas 1 octet. Vous le déplacez pour qu'il pointe sur **l'élément suivant** du même type.

La magie est que le compilateur connaît la taille du type pointé (sizeof(type)) et s'occupe du calcul :

  • ptr + 1 pour un int* avance de 1 * sizeof(int) octets (souvent 4).
  • ptr + 1 pour un char* avance de 1 * sizeof(char) octet (toujours 1).
  • ptr + i avance de i * sizeof(type) octets.
int numbers[] = {10, 20, 30, 40};
int *ptr = numbers; // ptr pointe sur le premier élément (10)

// Déplaçons le pointeur
ptr = ptr + 2; // ptr pointe maintenant sur le troisième élément (30)

L'expression ptr + 2 ne calcule pas 0x1000 + 2. Elle calcule :

Adresse de base + (Index * sizeof(int))
0x1000 + (2 * 4) = 0x1008

Le résultat est l'adresse de l'élément à l'index 2, qui est bien 30. La case est surlignée dans le diagramme ci-dessus.

Lien avec les Tableaux : Juste du Sucre Syntaxique !

En C, l'accès à un élément de tableau avec les crochets [] est directement lié à l'arithmétique des pointeurs. C'est pourquoi on dit que c'est du "sucre syntaxique".

Les deux expressions suivantes sont **strictement équivalentes** pour le compilateur :

valeur = array[i];
valeur = *(array + i);
  • array[i] : "Prends le i-ème élément du tableau." (Facile à lire)
  • *(array + i) : "Calcule l'adresse du i-ème élément en partant de 'array', puis déréférence ce pointeur pour obtenir la valeur." (Ce qui se passe réellement)

Opérations Courantes

Voici les opérations arithmétiques valides sur les pointeurs :

int numbers[] = {10, 20, 30, 40, 50};
int *p1 = &numbers[1]; // p1 pointe sur 20
int *p2 = &numbers[4]; // p2 pointe sur 50

// 1. Addition d'un entier à un pointeur
int *p3 = p1 + 3; // p3 pointe maintenant sur 50. (1 + 3 = index 4)
printf("%d\n", *p3); // Affiche 50

// 2. Soustraction d'un entier à un pointeur
p3 = p2 - 2; // p3 pointe maintenant sur 30. (4 - 2 = index 2)
printf("%d\n", *p3); // Affiche 30

// 3. Soustraction de deux pointeurs (du même tableau !)
// Le résultat est le nombre d'éléments qui les séparent.
int diff = p2 - p1; // diff = 4 - 1 = 3
printf("Il y a %d éléments entre p1 et p2\n", diff);

// 4. Incrémentation et Décrémentation
p1++; // p1 pointe maintenant sur 30 (index 2)
printf("%d\n", *p1);

p2--; // p2 pointe maintenant sur 40 (index 3)
printf("%d\n", *p2);

⚠️ Pièges et dangers

L'arithmétique des pointeurs n'est valide qu'à l'intérieur d'un seul bloc de mémoire alloué (comme un tableau). Tenter d'accéder à une mémoire en dehors de ce bloc (dépassement de tampon ou *buffer overflow*) conduit à un **comportement indéfini** (Undefined Behavior), la source de nombreux bugs et failles de sécurité.
