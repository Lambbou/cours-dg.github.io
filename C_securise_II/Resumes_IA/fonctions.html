Allocation Dynamique et Accès Mémoire en C 🧠

L'allocation dynamique permet de gérer la mémoire du **Tas (Heap)** au moment de l'exécution (runtime), contrairement à la mémoire de la **Pile (Stack)**. Elle est gérée par les fonctions de la librairie standard <stdlib.h>.

Les Quatre Cavaliers de l'Allocation Dynamique

1. malloc() : Allocation de Mémoire Brute

La fonction la plus courante. Elle alloue un bloc de mémoire d'une taille spécifiée en octets.

void* malloc( size_t size );
  • **Rôle :** Alloue size octets sur le Heap.
  • **Initialisation :** Les octets alloués contiennent des **valeurs indéterminées (garbage values)**. Vous devez les initialiser vous-même.
  • **Retour :** Un pointeur générique void* vers le début du bloc, ou NULL en cas d'échec d'allocation.

Exemple :

int *i_ptr = (int *) malloc( sizeof(int) ); // Alloue la taille d'un entier

2. calloc() : Allocation et Initialisation (Zérotage)

Utilisée principalement pour allouer des tableaux, car elle prend le nombre d'éléments et leur taille.

void* calloc( size_t num, size_t size );
  • **Rôle :** Alloue de la place pour num éléments de taille size (donc num * size octets au total).
  • **Initialisation :** **Initialise tous les octets alloués à zéro (0)**. C'est la différence clé avec malloc.
  • **Retour :** Un pointeur générique void* vers le début du bloc, ou NULL en cas d'échec.

Exemple :

int *arr = (int *) calloc( 5, sizeof(int) ); // Alloue 5 entiers et les met à 0

3. realloc() : Modification de la Taille

Utilisée pour changer la taille d'un bloc de mémoire précédemment alloué par malloc ou calloc.

void* realloc( void* ptr, size_t new_size );
  • **Rôle :** Redimensionne le bloc de mémoire pointé par ptr à new_size octets.
  • **Comportement :**
    • Si l'espace est suffisant **juste après** le bloc actuel, realloc peut simplement étendre le bloc et retourner la même adresse.
    • Sinon, realloc alloue un **nouveau** bloc ailleurs, copie le contenu de l'ancien bloc dans le nouveau, puis libère l'ancien.
  • **Retour :** La nouvelle adresse du bloc, qui peut être **différente** de ptr, ou NULL en cas d'échec.

Exemple :

arr = (int *) realloc( arr, 10 * sizeof(int) ); // Étend l'ancien tableau à 10 entiers

4. free() : Libération de la Mémoire

L'opération inverse et indispensable : rendre la mémoire au système pour qu'elle puisse être réutilisée.

void free( void* ptr );
  • **Rôle :** Libère le bloc de mémoire du Heap qui commence à l'adresse ptr.
  • **Pré-requis :** ptr doit avoir été retourné par un appel précédent à malloc, calloc, ou realloc.
  • **Effet :** Le bloc est libéré, mais ptr devient un **pointeur suspendu (dangling pointer)**.

Bonne Pratique : Toujours suivre free(ptr) par ptr = NULL; pour éviter l'utilisation accidentelle du pointeur suspendu.

Analyse du Code d'Exemple avec malloc

L'exemple suivant utilise malloc et met en lumière l'arithmétique des pointeurs et la libération manuelle.

const int array_size = 5;
int *array; // Pointeur sur la Stack
array = (int *) malloc( array_size * sizeof(int) ); // Allocation sur le Heap

if (array == NULL) { /* Gérer l'erreur d'allocation */ }

for (int i = 0; i < array_size; ++i) {
    // Équivalent à array[i] = i * i;
    *(array + i) = i * i; 
}

free(array); // Libération du bloc du Heap
array = NULL; // Évite le pointeur suspendu

Arithmétique des Pointeurs (L'accès aux données)

L'expression *(array + i) permet de parcourir le tableau alloué dynamiquement.

Le compilateur interprète array + i comme : **Adresse de base + (i * taille de l'entier)**. C'est ce qui permet de passer d'un élément à l'autre sans se soucier du nombre d'octets.

Étape 3 & 4 : Libération avec free et NULL

Après l'utilisation, **il est impératif** de libérer la mémoire pour éviter les **fuites de mémoire (memory leaks)**.

free(array);
array = NULL;
