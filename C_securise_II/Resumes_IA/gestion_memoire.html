Stack vs Heap en C : Comprendre la Gestion de la Mémoire 🧠

La gestion de la mémoire est un concept fondamental en programmation C. La mémoire allouée à votre programme est généralement divisée en plusieurs sections, dont les deux plus importantes pour l'allocation de données sont la **Stack (Pile)** et le **Heap (Tas)**.

---

La Stack (Pile) 🗼

Imaginez la Stack comme une pile d'assiettes : vous ajoutez (push) et retirez (pop) toujours par le haut. C'est une structure de type **LIFO** (Last-In, First-Out).

  • Allocation : **Automatique**. La mémoire est allouée et libérée automatiquement par le compilateur lorsque vous entrez et quittez une fonction.
  • Contenu : Stocke les **variables locales** (y compris les paramètres de fonction) et les **adresses de retour** des fonctions.
  • Vitesse : Très **rapide**, car la gestion est simple et structurée (seulement un pointeur est déplacé).
  • Taille : Généralement **petite** et **fixe** (définie au démarrage du programme ou du thread).
  • Durée de vie : Les données existent **seulement** pendant l'exécution de la fonction où elles sont déclarées.

Exemple en C (Stack)

void ma_fonction() {
    int a = 10;     // 'a' est stockée sur la Stack.
    char b[20];     // 'b' (un tableau) est stockée sur la Stack.

    // Quand ma_fonction se termine, 'a' et 'b'
    // sont automatiquement libérées de la Stack.
}
---

Le Heap (Tas) 🏞️

Le Heap est une grande zone de mémoire non structurée. C'est un espace plus libre, mais qui nécessite une gestion **manuelle** par le programmeur.

  • Allocation : **Dynamique**. Vous devez allouer la mémoire manuellement en utilisant des fonctions comme malloc(), calloc(), ou realloc().
  • Contenu : Utilisé pour stocker des données qui doivent survivre à la fin d'une fonction, comme des **structures de données complexes** (listes chaînées, arbres) ou des données de **grande taille**.
  • Vitesse : Relativement **plus lent**, car le système doit chercher un bloc de mémoire libre disponible (ce qui peut fragmenter la mémoire).
  • Taille : Généralement beaucoup **plus grande** que la Stack, limitée par la mémoire virtuelle du système d'exploitation.
  • Durée de vie : Les données existent **jusqu'à ce que vous les libériez explicitement** (avec free()) ou que le programme se termine. **Attention :** Oublier de libérer la mémoire provoque des **fuites de mémoire (memory leaks)** !

Exemple en C (Heap)

#include <stdlib.h>

void ma_fonction() {
    // 'ptr' (le pointeur) est sur la Stack.
    int *ptr = (int *)malloc(sizeof(int)); 

    if (ptr == NULL) { /* gestion d'erreur */ }

    *ptr = 100; // La valeur 100 est stockée sur le Heap.

    // **IMPORTANT :** Le bloc de mémoire pointé par 'ptr'
    // existera TOUJOURS APRÈS la fin de 'ma_fonction' !

    // Pour éviter une fuite, il FAUT le libérer :
    free(ptr); 
    ptr = NULL; // Bonne pratique
}
---

Tableau Comparatif Rapide ⚖️

Caractéristique Stack (Pile) Heap (Tas)
**Allocation** Automatique par le compilateur Manuelle par le programmeur (malloc/free)
**Vitesse** Très rapide Plus lent
**Durée de vie** Limitée à la fonction (portée locale) Jusqu'à libération explicite (portée globale potentielle)
**Taille** Petite et fixe Grande et variable
**Erreurs courantes** Dépassement de pile (Stack Overflow) Fuites de mémoire (Memory Leaks), double libération (Double Free), corruption de tas
---

En Résumé : Quand utiliser quoi ?

  • Utilisez la **Stack** pour la majorité des variables : celles dont vous connaissez la taille à la compilation et qui n'ont besoin d'exister que pendant l'exécution d'une seule fonction. C'est la méthode par défaut et la plus sûre.
  • Utilisez le **Heap** lorsque :
    • La taille de votre donnée n'est connue qu'à l'exécution (ex: un tableau dont la taille est lue à partir d'un fichier).
    • Votre donnée doit persister après le retour de la fonction qui l'a créée.
    • Votre donnée est très volumineuse et risquerait de provoquer un **Stack Overflow**.

Maîtriser ces deux concepts est essentiel pour écrire du code C efficace et sans bogue ! 👍
