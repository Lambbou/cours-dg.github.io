📐 L'Arithmétique des Pointeurs en C

L'arithmétique des pointeurs permet de naviguer dans les zones contiguës de mémoire. Contrairement à l'arithmétique entière classique, tout déplacement est automatiquement modulé par la taille du type pointé (sizeof(T)).

🎯 Le Principe Fondamental : Une Arithmétique Basée sur le Type

Lorsque vous additionnez 1 à un pointeur, le compilateur C n'ajoute pas un unique octet à l'adresse mémoire physique. Il fait pointer la variable sur l'élément suivant du même type.

Adresse résultante = ptr + (i × sizeof(*ptr))

Le compilateur déduit automatiquement le facteur d'échelle à partir du type de base :

  • ptr + 1 pour un int* avance de 1 × sizeof(int) = 4 octets (sur architecture 32/64 bits usuelle).
  • ptr + 1 pour un char* avance de 1 × sizeof(char) = 1 octet (toujours 1 par définition ISO C).
  • ptr + 1 pour un double* avance de 1 × sizeof(double) = 8 octets.
  • ptr + 1 pour une struct MaStructure* avance de sizeof(struct MaStructure) octets.
arithmetique_base.c 
int numbers[] = {10, 20, 30, 40};
int *ptr = numbers; // ptr pointe sur le 1er élément (&numbers[0] -> 10)

// Déplacement de 2 cases int (donc de 2 * 4 = 8 octets en mémoire)
ptr = ptr + 2;     // ptr pointe désormais sur le 3ème élément (numbers[2] -> 30)
printf("Valeur : %d\n", *ptr); // Affiche 30

📌 Décorticage du calcul
L'expression ptr + 2 ne produit absolument pas 0x1000 + 2 = 0x1002 (ce qui désalignerait l'accès pour un entier de 32 bits et entraînerait un crash sur certaines architectures matérielles). Elle calcule 0x1000 + 2 × 4 = 0x1008.

🍬 Tableaux et Crochets : Du Sucre Syntaxique !

En C, l'opérateur d'indexation avec crochets [] n'est qu'une écriture condensée de l'arithmétique des pointeurs combinée au déréférencement.

Syntaxe avec Crochets Arithmétique Pointeur Équivalente Interprétation Interne par le Compilateur
val = array[i]; val = *(array + i); Avance de i cases depuis array, puis lit le contenu.
&array[i]; array + i; Calcule l'adresse du i-ème élément.
array[0]; *array; Accède au tout premier élément à l'adresse de base.
💡 La curiosité de la commutativité en C
Comme l'addition est commutative (a + b == b + a), les expressions array[i] et i[array] produisent exactement la même opération interne : *(array + i). Bien qu'à proscrire pour la lisibilité, cette particularité illustre parfaitement la nature de l'indexation en C.

⚙️ Les Opérations Arithmétiques Valides en C

Le standard C autorise uniquement quatre opérations mathématiques sur les adresses :

1️⃣ Pointeur + Entier

Produit un nouveau pointeur décalé de n éléments vers l'avant.

p_suiv = ptr + 3;

2️⃣ Pointeur - Entier

Produit un nouveau pointeur décalé de n éléments vers l'arrière.

p_prec = ptr - 2;

3️⃣ Pointeur - Pointeur

Donne le nombre d'éléments séparant deux pointeurs du même tableau (type ptrdiff_t).

ptrdiff_t nb = p2 - p1;

4️⃣ Incrémentation & Décrémentation

Avance ou recule d'une case (ptr++, ptr--).

*ptr++ = valeur;
operations_pointeurs.c 
int tab[] = {10, 20, 30, 40, 50};
int *p1 = &tab[1]; // Pointe sur tab[1] (valeur 20)
int *p2 = &tab[4]; // Pointe sur tab[4] (valeur 50)

// Soustraction de 2 pointeurs : retourne le nombre de cases séparatrices
ptrdiff_t ecart = p2 - p1; 
printf("Écart en éléments : %td\n", ecart); // Affiche 3

// Attention aux priorités d'opérateurs :
int val1 = *p1++;   // Lit la valeur actuelle de *p1, PUIS incrémente le pointeur p1
int val2 = (*p1)++; // Incrémente LA VALEUR pointée par p1
🚫 Opérations STRICTEMENT INTERDITES en C
Il est formellement interdit de multiplier ou diviser un pointeur, ou encore d'additionner deux pointeurs entre eux (p1 + p2 est une erreur de compilation). De plus, soustraire deux pointeurs appartenant à des blocs mémoires différents conduit à un comportement indéfini.

⚠️ Pièges Critiques & Vulnérabilités de Dépassement

L'arithmétique des pointeurs ne bénéficie d'aucun mécanisme de contrôle des bornes (bounds checking) automatique au runtime. Si votre code calcule une adresse en dehors du bloc alloué :

  • Dépassement de tampon (Buffer Overflow) : Écrire au-delà de la taille allouée corrompt les variables adjacentes, la pile d'exécution ou les métadonnées du tas (Heap).
  • Comportement Indéfini (UB) : Le compilateur peut optimiser agressivement votre code sous l'hypothèse qu'un pointeur ne dépasse jamais les bornes, provoquant des anomalies de comportement inexplicables.
🛡️ La règle de l'adresse sentinelle (One-past-the-end)
Le standard C autorise explicitement à calculer l'adresse &array[taille] (soit un élément juste après la fin du tableau) pour servir de sentinelle d'arrêt dans une boucle. Cependant, il est strictement interdit de déréférencer cette adresse sentinelle (*(&array[taille]) déclenche un comportement indéfini).
