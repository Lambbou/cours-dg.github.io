⚙️ Fonctions Clés & Pointeurs de Fonctions

Maîtrise des quatre piliers de l'API standard <stdlib.h> pour l'allocation dynamique, piège critique du redimensionnement avec realloc, et sécurisation des pointeurs de fonctions (callbacks).

🏛️ Les Quatre Piliers de l'Allocation Dynamique (<stdlib.h>)

La gestion du Tas (Heap) repose sur quatre fonctions canoniques aux sémantiques et garanties bien distinctes :

1️⃣ malloc

void* malloc(size_t size);
  • Rôle : Réserve un bloc de size octets consécutifs.
  • Initialisation : Aucune ! La zone contient des garbage values (données résiduelles). C'est à vous qu'il revient d'initialiser le contenu.
  • Retour : Pointeur générique void* ou NULL si épuisement mémoire.

2️⃣ calloc

void* calloc(size_t nmemb, size_t size);
  • Rôle : Alloue un tableau de nmemb éléments de size octets chacun.
  • Initialisation : Tous les octets sont mis à 0 (zérotage matériel garanti).
  • Sécurité : Détecte en interne le dépassement de capacité entier (integer overflow).

3️⃣ realloc

void* realloc(void* ptr, size_t new_size);
  • Rôle : Agrandit ou rétrécit le bloc alloué précédemment.
  • Comportement : Étend sur place si possible, sinon alloue un nouveau bloc, copie le contenu et libère l'ancien.
  • Retour : Nouvelle adresse (peut différer de ptr) ou NULL en cas d'échec.

4️⃣ free

void free(void* ptr);
  • Rôle : Rends le bloc du Tas au système d'exploitation.
  • Contrat : ptr doit provenir d'un malloc/calloc/realloc valide.
  • Réflexe : Toujours faire suivre par ptr = NULL; pour éviter le pointeur suspendu.

⚠️ Le Piège Critique : Comment Utiliser realloc en Toute Sécurité

L'erreur classique des développeurs juniors consiste à réassigner directement le retour de realloc dans le pointeur d'origine :

❌ Le Motif Dangereux à Proscrire Absolument
// ERREUR GRAVE : Fuite de mémoire immédiate si realloc échoue !
buffer = (char *) realloc(buffer, nouvelle_taille);
if (buffer == NULL) {
    // buffer vaut désormais NULL, et l'ancien bloc n'a PAS été libéré !
    // L'adresse originelle est perdue à tout jamais : fuite irréversible (CWE-401).
}

Voici la méthode rigoureuse et défensive avec variable temporaire intermédiaire :

realloc_securise.c 
size_t nouvelle_taille = 1024 * sizeof(int);

// 1. Utiliser impérativement un pointeur temporaire
int *tmp = (int *) realloc(scores, nouvelle_taille);

if (tmp == NULL) {
    // L'ancien bloc pointé par 'scores' est TOUJOURS intact et accessible
    perror("Échec du redimensionnement");
    free(scores);   // Libération propre sans fuite si abandon
    scores = NULL;
    return -1;
}

// 2. Réassigner seulement après confirmation du succès
scores = tmp;

🎯 Les Pointeurs de Fonctions & Callbacks Sécurisés

En C, le nom d'une fonction évalue vers son adresse mémoire dans le segment de code (TEXT). Les pointeurs de fonctions permettent de concevoir des callbacks, des tables de sauts et des architectures polymorphes (comme qsort ou bsearch).

Syntaxe et Déclaration

pointeurs_de_fonctions.c 
// Signature : fonction prenant (int, int) et renvoyant int
int addition(int a, int b) { return a + b; }
int multiplication(int a, int b) { return a * b; }

// Déclaration d'un pointeur de fonction 'operation'
int (*operation)(int, int) = NULL;

// Affectation
operation = &addition; // ou simplement: operation = addition;

// Appel sécurisé : TOUJOURS vérifier que le pointeur n'est pas NULL !
if (operation != NULL) {
    int res = operation(10, 5); // ou (*operation)(10, 5) -> 15
}
🛡️ Enjeu de Sécurité Majeur (CWE-822 / Détournement de Flux)
Un pointeur de fonction non initialisé ou corrompu par un dépassement de tampon (Buffer Overflow) permet à un attaquant d'exécuter du code arbitraire s'il parvient à écraser l'adresse pointée (ex: technique ROP / ret2libc). En programmation défensive :
  • Toujours initialiser les pointeurs de fonctions à NULL.
  • Toujours vérifier if (callback != NULL) avant l'invocation.
  • Si possible, déclarer les tables de dispatch avec le mot-clé const pour qu'elles résident en mémoire en lecture seule (segment .rodata).

Exemple Réel : Callback avec typedef

callback_typedef.c 
// Clarté et robustesse grâce à typedef
typedef int (*comparateur_t)(const void *, const void *);

void trier_tableau(void *base, size_t n, size_t size, comparateur_t cmp) {
    if (base == NULL || cmp == NULL || n == 0) {
        return; // Échec gracieux défensif
    }
    qsort(base, n, size, cmp);
}
